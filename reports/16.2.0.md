### Tests added this run

Two new files, 41 tests, green on Node, Deno, and Bun, adding no type errors:

- `tests/sdk-sep53.test.ts` — SEP-53 message signing against the spec's own vectors, asserted in base64 and hex, with the `SHA256(prefix + message)` construction re-derived independently via `node:crypto` and checked through `verify` rather than `verifyMessage` so the two cannot drift from the spec together.
- `tests/sdk-new-api-behavior.test.ts` — `KeypairSigner`, `TransactionFailedError`, and the auth-entry inspection helpers.

A separate backlog pass followed the release verdict — not part of it — closing tier 1 of the coverage backlog (pure functions, no I/O): 101 tests across `sdk-strkey`, `sdk-numbers`, `sdk-claimant`, `sdk-contract-result`, and `sdk-config-helpers`, green on all three runtimes with no new type errors. That took the backlog from 248 to 164 and surfaced two new SDK findings, ISSUES.md issues 5 and 6. `StrKey` is covered with the official SEP-23 vectors, which is how issue 5 was found: the SDK accepts 4 of the 15 vectors the spec requires it to reject.

A third pass, also after the release verdict, closed the **end-user-distinct** work list — the 28 backlog symbols with no test in `js-stellar-sdk`'s own suite, identified by `coverage-audit.mjs --vs-upstream`. Four new files, 135 tests, green on all three runtimes, `tsc --noEmit` unchanged at 27:

`--vs-upstream` now reports `NO upstream test: 0`, and the overall backlog fell from 160 to 121 — every symbol still in it is one upstream already covers. One new SDK finding came out of it, ISSUES.md issue 11: `contract.Spec` decodes struct fields by position rather than by key, so `spec.scValToNative` and the SDK's own generic `scValToNative` return different objects for the same bytes. It is the same pattern as issue 5 — found only by feeding a decoder bytes it did not produce itself, which a same-spec round-trip cannot expose.

A fourth pass closed the gaps the third one exposed when its results were re-checked — the packaging axis the symbol audit could not see, and one method mis-credited to upstream. Two new files' worth of work, 47 tests, green on all three runtimes, `tsc --noEmit` unchanged at 27:

## Follow-ups

- ISSUES.md issue 1 closed. The fix is **not** the one originally proposed: the brittle `import { config }` from a vendored CJS path is still present verbatim, but the vendored `js-xdr` copy now ships `{"type": "module"}` with real `export { Reference, config }`, so the import never takes Node's CJS-interop path. The published `@stellar/js-xdr@4.0.0` package is unchanged.
- ISSUES.md issue 2 remains open and still blocked: `@stellar/js-xdr` is still `4.0.0`, CommonJS, and untyped, so the XDR-primitive type gaps cannot be closed without superseded hand-written types. Re-measure at v17.
- ISSUES.md issue 4 opened to track the 4 deferred surface locks.
- Behavior coverage added for all five new APIs — 41 tests in `tests/sdk-sep53.test.ts` and `tests/sdk-new-api-behavior.test.ts`, green on all three runtimes. The SDK matches all three official SEP-53 vectors byte-for-byte. Note the published SEP-53 document's base64 for vector 2 disagrees with its own hex by one bit; the hex is correct and matches the SDK.
- **ISSUES.md issue 12 opened, and it blocks.** The CJS half of the dual build `require()`s three ESM-only dependencies (`@noble/hashes`, `@noble/ed25519`, `uint8array-extras`), so `require("@stellar/stellar-sdk")` fails under Yarn Berry PnP and on any layout without Node's `require(esm)` support. Report upstream alongside issues 5, 8, and 11.
- ISSUES.md issues 11 and 13 opened; issues 7 and 13 closed. The coverage work list is done — `--vs-upstream` reports 0 symbols with no upstream test — and the audit now guards its own blind spot by diffing the SDK's `exports` map against the entry points it inventories.
- ISSUES.md issue 14 opened: `stellar-js generate` emits a package that fails its own TypeScript build because generated `Buffer` types have no Node globals.
- ISSUES.md issue 15 opened, and it blocks the Yarn Berry CLI axis: `corepack yarn stellar-js --help` crashes with `EBADF` in the PnP loader.
- Real-Chrome coverage now exercises all four published browser bundles; package artifact coverage locks exports, bin, and `dist` inventories.
