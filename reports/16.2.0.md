## Follow-ups

- ISSUES.md issue 1 closed. The fix is **not** the one originally proposed: the brittle `import { config }` from a vendored CJS path is still present verbatim, but the vendored `js-xdr` copy now ships `{"type": "module"}` with real `export { Reference, config }`, so the import never takes Node's CJS-interop path. The published `@stellar/js-xdr@4.0.0` package is unchanged.
- ISSUES.md issue 2 remains open and still blocked: `@stellar/js-xdr` is still `4.0.0`, CommonJS, and untyped, so the XDR-primitive type gaps cannot be closed without superseded hand-written types. Re-measure at v17.
- ISSUES.md issue 4 opened to track the 4 deferred surface locks.
- Behavior coverage added for all five new APIs — 41 tests in `tests/sdk-sep53.test.ts` and `tests/sdk-new-api-behavior.test.ts`, green on all three runtimes. The SDK matches all three official SEP-53 vectors byte-for-byte. Note the published SEP-53 document's base64 for vector 2 disagrees with its own hex by one bit; the hex is correct and matches the SDK.
